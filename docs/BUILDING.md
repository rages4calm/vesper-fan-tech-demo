# Building the shared demo

Players should download the Windows playable ZIP, not build from source.

## Open the source project

1. Clone this repository or download its source ZIP, using the **v0.3.2** tag for the initial public release.
2. Download **Vesper-v0.3.2-Source-Assets.zip** and **SHA256SUMS.txt** from [the v0.3.2 release](https://github.com/rages4calm/vesper-fan-tech-demo/releases/tag/v0.3.2).
3. Check the asset ZIP with PowerShell: `Get-FileHash .\Vesper-v0.3.2-Source-Assets.zip -Algorithm SHA256`. Compare it to SHA256SUMS.txt.
4. Extract that ZIP **into the repository root**. You should now have `godot/assets/vesper_city.glb`, alongside `godot/project.godot` and `godot/scripts/`.
5. Open `godot/project.godot` with **Godot 4.7.2 stable**. Let the imports finish, then press F6/F5 as appropriate to run the main scene/project.

Download Godot from its [official website](https://godotengine.org/download/windows/) or [official 4.7.2 release](https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable). Install the matching export templates through the editor before exporting a Windows build.

## Export Windows

```powershell
.\scripts\Build-Demo.ps1 -Godot 'C:\path\to\Godot_v4.7.2-stable_win64_console.exe'
```

The script uses the repository's Windows Desktop export preset and Godot's installed templates. No tools, credentials, editor caches, private saves, original UO client data, or original UO audio are required. The large assets are distributed as a release attachment instead of Git LFS objects.

The source asset ZIP contains the prepared GLB models, textures, font, UI artwork, original audio, and scene data needed to open and rebuild this Godot demo. It is **not** a complete archive of the private development workspace: raw downloaded source packs, Blender working files, prior builds, videos, and research downloads are excluded. The editable GLBs can be imported into Blender.

## Original audio generation

The bundled public effects and ambience are generated by `scripts/make_public_effects.py` and `scripts/make_ambience.py` with Python and NumPy. These scripts create new waveforms; they do not extract audio from Ultima Online.

## Native checks

The exported executable accepts QA modes. Run one at a time, with a writable output directory:

```powershell
.\build\Vesper\Vesper.exe -- --qa --qa-output=C:/temp/vesper-gameplay
.\build\Vesper\Vesper.exe -- --qa-harbor --qa-output=C:/temp/vesper-harbor
.\build\Vesper\Vesper.exe -- --qa-access --qa-output=C:/temp/vesper-access
.\build\Vesper\Vesper.exe -- --qa-route --qa-output=C:/temp/vesper-routes
.\build\Vesper\Vesper.exe -- --qa-render --qa-output=C:/temp/vesper-render
```

The gameplay check can additionally receive `--qa-music=C:/path/to/your-test.ogg` to test local soundtrack import. QA uses `qa_journey.json`, `qa_route_journey.json`, and `qa_music.*`, separate from normal player data. Rendering checks need a working GPU; do not run them headless.
